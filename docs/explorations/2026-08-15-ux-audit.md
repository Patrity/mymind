# UX audit — 2026-08-15

Walked the whole app as a user would: logged out → login → every nav item → settings
sub-pages, in both colour modes and at desktop + phone widths. Findings are ordered by
severity. Each one was reproduced in the browser; measurements are from the live DOM.

---

## S1 — Data loss and broken functionality

### 1. The document editor silently loses edits

**Reproduced.** Typed `LOSTTEXT` into `/input/transcribed-note-BSP_GVMI.md`, navigated to
`/tasks` immediately, read the doc back from the API: the text was gone. Control: text
typed and left alone for >1.5s persisted. So the loss is specific to the debounce window.

Three things combine (`app/components/documents/Editor.vue`):
- autosave is debounced **1.5s** (`saveTimer = setTimeout(() => saveContent(), 1500)`)
- `saveStatus` is `idle` during that window, so the UI shows **nothing** — no dirty dot,
  no "unsaved"
- there is **no `beforeunload` and no `onBeforeRouteLeave` guard anywhere in `app/`**

A user who types a sentence and clicks a nav link loses it with no warning and no trace.

**Fix:** show a dirty indicator the moment `content !== savedContent`; flush the pending
save on route leave / `beforeunload`; add a `beforeunload` guard while dirty.

### 2. The agent chat is unusable on a phone

At 390×844 the message composer is in the DOM but measures `{x:0, y:0, width:0}` —
the Transcript panel collapses to zero width and takes the input with it. The visualiser
canvas fills the entire viewport. There is no way to send a message on mobile.

**Fix:** below the panel breakpoint, drop the visualiser to a small header element (or
hide it) and give the transcript + composer the full width.

### 3. Clipboard's Copy button never appears on touch devices

All **16** Copy buttons on `/clipboard` compute to `opacity: 0` at 390px. They're gated
behind `opacity-0 group-hover:opacity-100` (`clipboard/MessageText|Image|Video.vue`).
Touch devices have no hover, so the button never reveals.

This is the one feature whose whole purpose is phone ↔ desktop transfer, and its primary
action is unreachable on the phone.

**Fix:** always-visible actions at touch widths (or `@media (hover: hover)` gating).

### 4. Editor text fails WCAG AA badly in light mode

`CodeEditor.client.vue` loads `oneDark` **unconditionally** — no `useColorMode()` check.
The dark theme's foreground lands on the app's light surface:

| Mode | Foreground | Background | Contrast | WCAG AA (4.5:1) |
|---|---|---|---|---|
| Light | `rgb(171,178,191)` | `rgb(255,255,255)` | **2.13:1** | ✗ fails |
| Dark | `rgb(171,178,191)` | `oklch(0.205 0 0)` | 7.73:1 | ✓ passes AAA |

The app's primary writing surface is near-illegible for anyone in light mode. Affects
every `CodeEditor` instance, not just documents.

**Fix:** swap the theme extension on `useColorMode()` via a compartment.

## S2 — Significant friction

### 5. Tasks' primary CTA is clipped off-screen on mobile

At 390px the "New task" button's right edge is at **410px** — 20px past the viewport. The
header row overflows horizontally and the `h1` collapses to `width: 0`.

### 6. Deep links are discarded at login

`app/middleware/auth.global.ts` does `navigateTo('/login')` with no `redirect` query, and
`login.vue` always lands on `/documents`. Bookmark `/projects/mymind`, come back tomorrow,
end up on Documents. Every share/bookmark of a non-default page is lost.

### 7. Truncated labels with no tooltip, app-wide

**0 of 24** `.truncate` spans on the documents page carry a `title` attribute. Truncated
text is therefore permanently unreadable.

Worst offenders:
- Document tree: two different docs both render as `Transcri…` (71px label in a 135px row).
  The hover-only delete button still occupies layout width even at `opacity-0`, stealing
  ~28px from every filename.
- Sidebar search button: `Searc… ⌘K`
- Settings sub-nav: `Model Co…`
- Agent model picker: `Default (chain ord…`

**Fix:** `:title` on truncated labels (or a `UTooltip`); take the hover-only delete button
out of flow (`absolute`) so it stops eating label width.

### 8. Keyboard and screen-reader dead ends

- Task cards are bare `<div @click>` — no `role`, no `tabindex`, not a `<button>`
  (`tasks.vue:388`). `main` contains **0** focusable elements. Opening a task is
  mouse-only.
- Project rows are the same pattern (`projects/index.vue:153`), with the edit button
  additionally hover-gated.
- 6 components hide their actions behind `opacity-0 group-hover` — unreachable by keyboard
  and by touch.
- The tree's delete buttons have no accessible name (snapshot shows bare `button`).

### 9. Search palette (⌘K) repeats itself

- Every memory/message result prints its **title as its own description** — the row is the
  same sentence twice.
- The same item appears in "Top results" **and** again under "Memories" — you can't tell
  duplicates from two real records.
- The pre-query empty state is literally **"No data"**, which reads as an error. Should be
  recents or "Start typing".
- No `↑↓ / ↵ / esc` hints.

## S3 — Consistency and polish

### 10. Four date formats for the same kind of value

| Page | Rendering |
|---|---|
| `/projects` | `Active Jun 16, 2026` |
| `/projects/mymind` | `Active 2 months ago` |
| `/review` | `6/17/2026, 5:15:14 AM` |
| `/settings/api-keys` | `8/14/2026` |

The same field (`lastActivityAt`) renders absolute on the list and relative on the detail.
Sessions show everything as "2 months ago", so nothing can be ordered by eye.

### 11. Hard-coded plurals — 11 instances across 5 files

`1 sessions`, `1 tools`, `0 memories`. Locations: `ProjectMergeModal.vue` (3),
`projects/index.vue` (2), `projects/[slug].vue` (2), `sessions/index.vue` (2),
`sessions/[id].vue` (1).

### 12. Unlabeled controls

- `/projects`: **7** `USwitch`es with no `aria-label`, no visible label, no tooltip. Nothing
  says they mean "active", and nothing says what "active" does. (It only filters
  `?active=true` — low stakes, zero explanation.)
- Sessions/projects: `↑ 163.1M  ↓ 938.2k` — token counts as bare arrows, no label.
- Document tree delete buttons: no accessible name.
- `/activity` second filter reads just "All".

### 13. Review queue works against itself

- The recommended action **"Accept (archive old)" is styled `color="error"` (red)** while
  the passive "Keep both" is a ghost button. Red = destructive by convention; this inverts
  the hierarchy on the action you usually want.
- 13 pending items with **no progress indicator** ("1 of 13") and no keyboard shortcuts —
  it's a triage queue that requires a mouse round-trip per decision.
- No undo after accepting (it archives the old memory).

### 14. One-off patterns that break the design language

- `tasks.vue:232` uses native **`window.confirm()`** for delete; everywhere else uses a
  styled `UModal`. It's the only native dialog in the app.
- The task modal's due date is a raw `<input type="date">` (`mm/dd/yyyy`) sitting next to
  Nuxt UI selects.
- **No `app/error.vue`** — 404s fall back to Nuxt's stock page, which ignores dark mode
  (white page after browsing dark), has no app shell, and prints the error message twice.

### 15. Density and layout

- `/agent`: the visualiser takes ~70% of the width; the transcript gets ~275px. For a chat
  UI the priority is inverted, and the empty transcript has no empty state at all.
- `/galaxy`: six developer tuning sliders (cluster spread, glow, link opacity…) are open by
  default as the primary UI.
- `/capture`: title input and note textarea sit in two columns with the Capture button
  orphaned under the title; the whole form is a ~380px column in a 1100px space.
- `/documents`: two `<h1>Documents</h1>` on one page (tree header + panel header); the panel
  header should carry the open document's name.
- `/settings/providers`: ~135px of vertical space per provider for three short lines.
- `/settings/model-config`: "Drag to set failover priority (first = primary)" repeated
  under all four groups.
- `/analytics`: the 1h/6h/24h/7d segmented control spans ~1000px for four options; the GPU
  chart auto-scales its axis to 0–1% on flat-zero data and reads as broken.
- `/gallery`: "7 suggested" badge plus a lock icon on nearly every tile — the exception
  (public) is what deserves the marker, not the norm. OCR text tiles render clipped
  mid-word at large size and look broken.

### 16. Smaller items

- `/settings/api-keys`: two tokens render as `mm_…????` (missing `last_four`). Revoked rows
  can't be deleted, so they accumulate forever, and aren't dimmed.
- `/activity`: the log is dominated by the app's own fetches (`/api/memories/count`,
  `/api/review/count`, `/api/_nuxt_icon/lucide.json`), burying real errors. The mitigation
  (Capture → `inbound` toggle) is on by default and buried in settings.
- Login: no autofocus on the email field; no password-reset path at all.
- Editor has no `lineWrapping` — on a 390px screen every long line scrolls horizontally.
- `/api/_nuxt_icon/lucide.json` 401s on the login page (icons still render from the
  bundle in dev; worth confirming on a cold prod cache).
- Completed tasks look identical to open ones — only column position conveys done-ness.
- Empty kanban columns get a dashed bordered box; populated ones don't.

## What's already good

Worth protecting when fixing the above:

- `/settings/alerts` is the model page: every toggle labeled, sections explained, explicit
  Save. It's the pattern the Projects toggles should copy.
- `/settings/skills`: clear name + description + when-to-use, per-item toggle, global
  switch.
- Task creation: autofocus + Enter-to-submit works.
- The kanban uses `useSortable` as intended.
- Most pages have real `USkeleton` loading states (15 files).
- Escape closes modals; the sidebar collapse/resize works well.
- `/settings/secrets` empty state does the right thing (explains, then inlines the form).

---

## Suggested order of work

1. Editor dirty-state + save-on-leave (#1) — it destroys user data today.
2. `oneDark` colour-mode swap (#4) — one-line-ish fix, large legibility win.
3. Mobile: agent composer (#2), clipboard copy (#3), tasks header (#5).
4. Login redirect preservation (#6).
5. `:title` on truncated labels (#7) + take hover-delete out of flow.
6. Focusable rows/cards (#8).
7. A shared `formatDate`/`pluralize` pass (#10, #11).
8. `app/error.vue` (#14).
