# Outcome Judge + Eval Substrate Implementation Plan (cycle 85, harness step 6a)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every `finish_workstream` is verified against the goal (≤ 2 send-backs, never blocks), and Bridget gets scored eval suites that run headless against a recorded fake world, tracked per commit/model/prompt on `/evals`.

**Architecture:** `judge/outcome.ts` (evidence + verifier) wired into `finish_workstream`; `packages/core/src/lib/eval/` (`world.ts` fake Gmail/Calendar/web + capture, `tenant.ts` isolation, `matcher.ts`, `score.ts`, `runner.ts`); worker job `eval:run-suite`; `pnpm eval` CLI; `/evals` pages.

**Tech Stack:** `@mymind/core`, worker, drizzle, AI SDK v6, Nuxt UI, vitest, playwright-cli.

**Spec:** `docs/superpowers/specs/2026-10-13-eval-design.md`

## Global Constraints

- Outcome verdict `met|partial|unmet`, confidence 0–1, gaps ≤ 5 × ≤ 200 chars, nextStep ≤ 300 chars; `met` requires confidence ≥ 0.7; **≤ 2 send-backs**; verifier error/timeout (60 s, shares the judge semaphore) never blocks finishing; never `failed` by the verifier.
- Evidence caps: last 60 tool calls (args digest ≤ 200, result digest ≤ 300 chars), workspace diff ≤ 8 KB; everything but the goal fenced untrusted (random fence, defang — as in cycle 84).
- Eval isolation: every row an eval run writes is tagged with `eval_run_id` (or lives in a dedicated schema) and is **invisible to every normal query and API**, and deleted after the run; the fake world makes **zero network calls** and never touches real Google accounts, iMessage, outbox or notifications; writes are captured.
- Eval segments use at most `floor(maxInFlight / 2)` (min 1) of each model's pool; per-attempt wall cap 10 min.
- Scoring exactly per spec §3.4 (attempt = action × content × (outcome met ? 1 : 0.5); forbidden → 0; case passes at mean ≥ 0.8 with no forbidden hit).
- Gates: typecheck, test, test:db, build, worker build + `node apps/worker/stage.mjs <dir>`. Conventional commits, **no attribution trailers**. Commit first, mutate, restore with `git checkout`; never `git stash`. `expect.stringMatching`, never a bare RegExp in `toMatchObject`. Dev DB shared — own `MYMIND_BUS_NS`, clean rows. Kill only your own PIDs.

## Review Focus
1. **Eval leaking into real life** — a real email/calendar write, a network call, an iMessage, an eval row visible in Tony's tasks/memories/docs/threads, cleanup misses.
2. **Verifier loops / blocks** — send-back counting across segments/restarts, coordinator verification recursion, a verifier error stalling finish.
3. **Verifier injection** — fenced evidence, the verifier's output steering the run (it only gates finishing).
4. **Score correctness** — matcher edge cases (repeated tools, args_pattern on non-strings), holdout excluded from aggregate "non-holdout" numbers.
5. **Pool/starvation** — eval jobs crowding Tony's chat/workstreams.
